# 深刻理解编译链接

## 一、 编译器驱动程序 (从文本到机器码)
- **核心本质**：`g++` 是调度四大工具 (cpp, cc1plus, as, ld) 的驱动程序包工头。
- **四大阶段**：
  - 预处理 (`-E`)：纯文本替换，宏展开，去注释（无模板实例化）。
  - 编译 (`-S`)：AST 树构建，语义分析，生成汇编（模板在此阶段实例化）。
  - 汇编 (`-c`)：翻译为机器码，生成 `.o` 文件。
  - 链接：打包多个机器码文件为可执行程序。
- **设计价值**：实现流水线解耦，汇编器与链接器可跨语言复用。

## 二、 可重定位目标文件 (ELF 格式)
- **核心本质**：内部地址皆为从 0 开始的相对偏移量，尚未分配绝对内存地址。
- **物理结构 (Section 视图)**：
  - `.text`：只读机器指令。
  - `.rodata`：只读常量。
  - `.data`：已初始化的全局/静态变量。
  - `.bss`：未初始化的全局/静态变量（仅在 ELF 头占位，不占磁盘空间）。
- **架构价值**：按权限分离代码与数据，保证执行安全，提高 CPU 缓存命中率，允许多进程共享同一 `.text` 段物理内存。

## 三、 符号与符号表 (.symtab)
- **核心本质**：链接器眼中的全局变量与函数名的统一抽象（局部变量在栈上，无符号）。
- **强弱符号陷阱**：
  - 强符号：已初始化全局变量、函数定义。
  - 弱符号：未初始化全局变量。
  - 霸王条款：强弱选强。同名弱符号覆盖强符号且类型大小不一致时，会导致极其隐蔽的内存越界踩踏血案。
- **工程避坑**：C++ 为了支持重载存在名字粉碎机制，调用 C 库必须加 `extern "C"` 防护。

## 四、 符号解析与静态库 (.a)
- **核心本质**：静态库是使用 `ar` 工具打包的一堆 `.o` 文件的压缩包，并附带全局符号索引表。
- **符号解析**：将未定义符号 (U) 精准绑定到已定义符号 (T/D) 的“相亲匹配”过程。
- **架构价值**：实现空间复用与“按需提取”，链接器只抽取被真正用到的 `.o` 模块，拒绝死代码膨胀。

## 五、 静态库解析算法 (单向扫描)
- **核心机制**：从命令行左向右死板扫描，维护 E (实体)、U (未解析需求)、D (已解析供给) 三大集合。
- **工程避坑**：调用方必须严格写在被依赖库的左边，否则链接器遇到无需求的库会直接丢弃，导致最终报错 `undefined reference`。

## 六、 重定位 (最后的外科手术)
- **空间分配 (合并)**：将所有入选 `.o` 文件的同类 Section (如 `.text`) 合并，并为它们分配最终的虚拟内存绝对地址 (VMA)。
- **指令打补丁**：查阅 `.rel.text` 和 `.rel.data` 备忘录，根据偏移量和重定位规则，算出真地址并精确覆盖原本预留的假地址 (如 `e8 00 00 00 00`)。

## 七、 动态库与位置无关代码 (.so)
- **核心痛点**：物理内存共享要求代码段必须“只读且不含绝对地址”，以应对随机装载 (ASLR)。
- **黑魔法解法 (-fPIC)**：
  - **GOT (全局偏移表)**：位于私有数据段，存放运行时回填的真地址。
  - **PLT (过程链接表)**：位于共享代码段，充当相对寻址跳板。
- **延迟绑定**：首次调用经 PLT 查 GOT，唤醒动态链接器寻址并回填；后续调用查 GOT 直接极速起飞，极大优化启动性能。
- **工程落地**：遇到运行时 `cannot open shared object file` 报错，必须将库放入系统目录并执行 `sudo ldconfig` 刷新装载器缓存名单。
