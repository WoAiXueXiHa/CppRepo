# C++ 指针与内存管理核心体系

## 一、 指针基础

### 1. 核心本质
* **定义**: 存放内存地址的变量（OS寻址决定大小：32位4B，64位8B）
* **指针步长**: 决定 `p+1` 跨越的物理字节数（结合强转可做字节流解析）

### 2. 指针的羁绊
* **指针 vs 引用**:
  * **本质**: 物理实体 vs 逻辑别名 (底层为指针常量)
  * **约束**: 指针自由可为空；引用必须初始化、终生绑定、不可为空
  * **sizeof**: 测指针本身大小 vs 测绑定对象大小
* **const 迷阵**: 
  * `const int* p` (保护数据，数据只读)
  * `int* const p` (保护指针，指向不可变)

### 3. 危险与特型指针
* **三类危险指针**: 
  * **空指针**: 解引用触发 MMU 缺页导致 `SIGSEGV` 崩溃
  * **野指针**: 未初始化
  * **悬空指针**: 释放后未置空
* **void* 指针**: 纯物理地址，无步长，不可解引用/加减，强转后方可用

### 4. 高阶内存布局
* **指针与数组**: 数组名通常退化为首元素地址 (`sizeof` 和 `&` 例外)；区分指针数组(数组装指针)与数组指针(指针指数组)
* **函数指针**: 存储代码段机器指令起始地址，实现**回调机制**
* **内存对齐**: 空间换时间。受制于**成员自身**和**结构体整体**对齐规则 (网络序列化需 `#pragma pack(1)` 取消对齐)
* **大小端字节序**: 
  * **大端**: 高位存低地址 (符合阅读习惯)
  * **小端**: 低位存低地址 (低对低)
  * **验证手法**: `char*` 指针强转探测、联合体 (`union`) 共享起始地址探测

## 二、 内存管理

### 1. 底层机制剖析
* **malloc / free (库函数)**: 
  * 纯粹分配/回收物理内存字节，无视对象生命周期。
* **new / delete (运算符)**:
  * `new`: `operator new` (底层调用 malloc) -> 触发**构造函数**
  * `delete`: 触发**析构函数** -> `operator delete` (底层调用 free)
* **new[] / delete[] (数组管理)**:
  * 核心: 编译器分配多余头部空间 (**Cookie**) 记录元素数量 N。
  * `new[]`: 分配总内存 -> 填入 N -> 循环 N 次构造
  * `delete[]`: 读头部 N -> 倒序循环 N 次析构 -> 释放总内存

### 2. 实战与踩坑指南
* **三大核心区别 (new vs malloc)**:
  1. 本质动作不同 (是否涉及对象构造/析构)
  2. 类型与异常 (天生强类型+抛出 `std::bad_alloc` 异常 vs 弱类型+返回 `NULL`)
  3. 架构重载能力 (new/delete 可重载以实现自定义内存池)
* **两大夺命死穴**:
  1. **new 配 free**: 内存泄漏 (不调析构，导致对象内部申请的动态资源丢失)
  2. **new[] 配 delete**: 资源泄露/UB (找不到头部 Cookie，仅析构第 0 个元素，跳过后续元素)
